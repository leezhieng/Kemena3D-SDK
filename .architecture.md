# Kemena3D Project Architecture

## Overview

Kemena3D is an open-source, cross-platform C++17 3D game engine with three components:

---

## 1. `Kemena3D-SDK/` — Kemena3D SDK (Core Engine Library)

The core 3D rendering engine, built as a static (or shared) C++ library.

**Tech Stack:**

- C++17, CMake (MSVC 2026, MinGW/GCC, Clang/Xcode, Android NDK)
- **Renderers:** OpenGL 3.3/4.5, DirectX 11 (Windows), OpenGL ES 3.0 (Android/mobile)
- SDL3 (windowing/input)
- ImGui + ImGuizmo (UI, docking branch)
- Jolt Physics, Recast/Detour (navigation)
- Assimp (mesh import, optional) or tinygltf (glTF/GLB only)
- AngelScript (scripting), GLM (math), miniaudio (audio)
- nlohmann/json, portable-file-dialogs, stb_image

### Asset Packaging System

The SDK includes a built-in asset packaging system for game distribution.

#### Virtual File System (`kfilesystem.h`)

`kFileSystem` is a global singleton that transparently routes file I/O to either:
- **Editor/Development mode:** Direct OS filesystem access (no change in behavior)
- **Packaged/Runtime mode:** Reads from a `.kpak` archive mounted next to the executable

```cpp
// Initialize before any asset loading
kFileSystem::init(exeDirectory, "data");

// Transparent file access — works in both modes
if (kFileSystem::fileExists("scene.world")) { ... }
auto data = kFileSystem::readFile("Library/ImportedAssets/abc.glb");
kString json = kFileSystem::readFileString("game.config");

// For APIs that need a real OS path (e.g. Assimp mesh loading)
kString osPath = kFileSystem::resolveOSPath("Library/ImportedAssets/abc.glb");

// Check if running packaged
bool packaged = kFileSystem::isPackaged();

// Shutdown
kFileSystem::shutdown();
```

**Startup detection order:**
1. Look for `<exeName>.kpak` next to the executable
2. Look for `data.kpak` next to the executable
3. Look for `data/` folder next to the executable
4. Fall back to the executable directory itself

#### Package Format (`.kpak`)

```
[Header - 16 bytes]
  Magic:       "KPAK"         (4 bytes)
  Version:     uint32_t = 1   (4 bytes)
  Flags:       uint32_t       (4 bytes)  [bit 0 = has-compressed-entries]
  EntryCount:  uint32_t       (4 bytes)

[File Index - repeated EntryCount times]
  PathLength:        uint16_t  (2 bytes)
  Path:              char[]    (PathLength bytes, UTF-8)
  DataOffset:        uint64_t  (8 bytes)  absolute byte offset
  CompressedSize:    uint32_t  (4 bytes)  0 = uncompressed
  UncompressedSize:  uint32_t  (4 bytes)

[File Data] — concatenated raw or LZNT1-compressed blobs
```

Paths use forward slashes relative to package root:
- `scene.world`
- `game.config`
- `Library/ImportedAssets/abc123.glb`
- `Library/Scripts/abc123.kbc`

**Compression:** On Windows, uses the built-in `RtlCompressBuffer`/`RtlDecompressBuffer` (LZNT1) from `ntdll.dll` — zero external dependencies. Per-file compression enables O(1) random access to any asset without decompressing the entire archive.

### Animation System

Skeletal animation is played back by `kAnimator`, which turns one or more
`kSkeletalAnimation` clips into a per-bone matrix palette for the skinning
shader. The animator supports three ways of combining clips:

| Feature               | Type(s)                                            | What it does                                                                 |
| --------------------- | -------------------------------------------------- | ---------------------------------------------------------------------------- |
| **Cross-fade**        | `kAnimator::beginBlend()`                          | Local-space blend of two clips over a duration for smooth state transitions. |
| **Partial animation** | `kAnimationMask`, `kPoseSample::mask`              | Blends only the bones a mask enables; other bones keep the rest pose.        |
| **Additive animation**| `kAdditiveAnimation`, `kPoseSample::additive`      | Layers `(pose - reference) * weight` on top of the base pose.                |

#### Partial animation (masks)

`kAnimationMask` names a subset of a skeleton's bones and is built from a
skeleton hierarchy, a bone-name list, or a skinned mesh's bone palette. Bones
can be toggled individually or by humanoid body part (name-based classification
that understands `Left`/`Right`, `_L`/`_R`, `LeftArm`, `RightUpLeg`, …).

```cpp
kAnimationMask upperBody("UpperBody");
upperBody.buildFromSkeleton(clip->getRootNode(), false /* start disabled */);
upperBody.setBodyPartEnabled(kAvatarBodyPart::Spine,    true);
upperBody.setBodyPartEnabled(kAvatarBodyPart::Head,     true);
upperBody.setBodyPartEnabled(kAvatarBodyPart::LeftArm,  true);
upperBody.setBodyPartEnabled(kAvatarBodyPart::RightArm, true);

kPoseSample s;
s.animation = upperBodyClip;
s.time      = t;
s.weight    = 1.0f;
s.mask      = &upperBody; // only these bones contribute; the rest use the base pose
```

`kAnimator::beginBlend(..., const kAnimationMask *mask)` applies the same idea
to a two-clip cross-fade: masked bones fade, everything else snaps to the
destination clip.

##### Authored bone-mask groups & per-state weights

The editor layers an authoring workflow on top of `kAnimationMask`:

- **Authoring — Mesh Inspector → Import Settings → Bone Masks.** Pick a bone
  range (start bone → end bone) from the model's skeleton and save it under a
  custom name (e.g. `LowerArm`). The groups are written to the mesh asset's
  metadata and mirrored into `Config/import_settings.json` (`boneMasks`), so
  they survive re-imports and travel with the project through git.
- **Weighting — Animator Inspector → Mask Weights.** Every state *and* blend tree
  can reference any group authored on its bound mesh and give it a weight in
  `[0,1]`.
- **Runtime — `Manager::stepAnimators()`.** A state's weights are turned into
  pose samples: for each masked region the clip sample carries weight `w` and a
  paired `kPoseSample::restPose` sample carries `(1 - w)`. That makes `w` an
  absolute "how strongly does this state drive the region" control — `0` leaves
  the region at the rest pose, `1` fully drives it — while a single blend tree
  lets several motions each declare their own regional influence. Bones that no
  group covers are driven at full strength.

#### Additive animation

`kAdditiveAnimation` bakes a reference pose (`buildFromBindPose()` or
`buildFromClip()`) and samples each bone's delta relative to it
(`sampleDeltaMatrix()`). Setting `kPoseSample::additive` makes the blended-pose
pass layer that delta onto the base pose — position/scale additively, rotation
multiplicatively — so effects such as hit reacts, leans or aim offsets play over
any locomotion state without authoring combination clips.

```cpp
kAdditiveAnimation lean;
lean.setClip(leanClip);
lean.buildFromClip(baseClip, 0.0f); // bake baseClip frame 0 as the reference

kPoseSample a;
a.animation = leanClip;
a.time      = leanTime;
a.weight    = 0.5f;
a.additive  = &lean;
```

Both features are evaluated inside
`kAnimator::calculateBlendedBoneTransform()` in two layers — base samples first,
then additive samples — so a single hierarchy traversal produces the final pose.

## 2. `Kemena3D/` — Kemena3D (Editor)

Full-featured game editor with dockable ImGui panels.

**Architecture:**

- Single executable (`main.cpp`, ~810 lines) linking against the SDK
- ImGui docking for panel-based UI layout
- ImGuizmo for 3D manipulation gizmos (translate/rotate/scale)

**Editor Panels** (in `src/panel_*.cpp`):

| Panel               | Purpose                                                              |
| ------------------- | -------------------------------------------------------------------- |
| `PanelWorld`        | 3D viewport (orbit/pan/zoom, object picking, outlines, debug shapes) |
| `PanelInspector`    | Property inspector for selected objects/components                   |
| `PanelHierarchy`    | Scene tree view                                                      |
| `PanelProject`      | Asset browser (file management, drag-drop, thumbnail generation)     |
| `PanelConsole`      | Log/output console                                                   |
| `PanelShaderGraph` | Visual GLSL shader graph editor                                      |
| `PanelLogicGraph` | Visual node-graph script editor (AngelScript)                        |
| `PanelGame`         | Play/Pause/Stop controls, game view                                  |
| `PanelPrefab`       | Prefab editing mode                                                  |
| `MainMenu`          | File/Edit/View/Run/Help + keyboard shortcuts                         |
| `SplashScreen`      | Project creation/open dialog                                         |
| `crashhandler.cpp`  | Crash reporter (`Kemena3D_crash.log` with DbgHelp stack traces)      |

**Key Features:**

- Undo/Redo system (`commands.cpp`)
- Drag-drop asset import from OS
- Object picking via color-ID rendering pass
- Selection outlines (orange) + drag-hover outlines (yellow)
- Editor camera: Alt+drag orbit, middle-mouse pan, wheel zoom
- F key: frame-focus selected with smoothstep tween
- W/E/R keys: translate/rotate/scale gizmos
- Ctrl+S/D/Delete/Z/Y shortcuts
- Octree debug visualization, NavMesh wireframe debug
- Script hot-reload while stopped
- Editor grid on "Editor Scene"
- Layout persistence (ImGui .ini serialization)
- Prefab editor with isolated offscreen rendering
- **Game Export:** Packages all assets into a single `.kpak` file for distribution

## 3. `Kemena3D-Runtime/` — Kemena3D Runtime (Player/Export Template)

Generic, game-agnostic standalone executable. Same binary ships with every exported game; only `data/` (or `<game>.kpak`) differs.

**Flow:**

1. Initialize VFS: auto-detect `.kpak` package or `data/` folder relative to executable
2. Read `game.config` via VFS (JSON: title, width, height, fullscreen)
3. Boot engine: window → renderer → asset manager → world
4. Load `scene.world` via VFS
5. Start physics + scripts
6. Game loop: fixed-update scripts → physics step → update scripts → render
7. Cleanup + VFS shutdown on exit

**Export layout:**

```
MyGame/
├── MyGame.exe              (renamed Kemena3D-Runtime)
├── MyGame.kpak             (all game assets in one file)
├── SDL3.dll                (runtime dependencies)
├── assimp.dll
└── ...
```

~130 lines of `main.cpp`. No ImGui/editor dependencies. Can build with `KEMENA_USE_ASSIMP=OFF` for glTF/GLB-only slim builds.

## Graphics Backends

The engine uses an abstract `kDriver` interface that allows swapping graphics APIs at runtime.

| Backend | Enum Value | Platform | Driver Class | Build Flag |
|---------|-----------|----------|-------------|------------|
| **OpenGL 3.3 / 4.5** | `RENDERER_GL` | All desktops | `kOpenGLDriver` | *(always built)* |
| **OpenGL ES 3.0** | `RENDERER_GLES` | Android / mobile | `kOpenGLESDriver` | `KEMENA_GLES=ON` |
| **DirectX 11** | `RENDERER_D3D11` | Windows | `kDX11Driver` | `KEMENA_D3D11=ON` |

All asset loading (textures, shaders, meshes) and rendering goes through the driver.
HLSL shaders (`.hlsl`) are used for D3D11; GLSL (`.glsl`) for OpenGL / GLES.

## Build System

### Desktop

- **SDK:** `build_sdk.py` — interactive, builds with CMake, outputs to `Output/{Debug,Release}/`
- **Editor:** `build_editor.py` — links against SDK output
- **Runtime:** `build_runtime.py` — links against SDK output
- **Deps:** `download_dep.py` — fetches all third-party dependencies

`build_sdk.py` asks which renderers to include based on the platform:
- Windows: OpenGL only, or OpenGL + DirectX 11
- Linux/macOS: OpenGL (auto-selected)

### Android

- **Deps:** `download_dep_android.py` — cross-compiles dependencies for Android (ARM64/ARMv7)
- **SDK:** `build_sdk_android.py` — cross-compiles the SDK using the Android NDK toolchain

```powershell
# 1. Download & cross-compile dependencies
python download_dep_android.py --ndk-path C:/android-ndk-r27 --abi arm64-v8a

# 2. Build SDK
python build_sdk_android.py --ndk-path C:/android-ndk-r27 --abi arm64-v8a
```

Output: `Output/Android_arm64-v8a/Release/`
